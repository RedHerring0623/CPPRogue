# 执行可视化 Demo（DemoUI）

> 对应代码：仓库根目录 `DemoUI/`（WinForms，**不在 Unity 工程内**）
> 用途：开发期用肉眼验证"代码执行"的观感——语句高亮、节奏、优化掉/卡死的演出。
> 它链接着 Unity 项目里的同一份 Core 源码（真解释器驱动，不是模拟）。

---

## 1. 运行

仓库根目录：

```bash
dotnet run --project DemoUI
```

不需要 Unity。改了 Core 代码重跑这条命令即可。

## 2. 界面说明

| 区域 | 内容 |
|---|---|
| 左上：语法块面板 | 可拖入的块（attack/if/for/while/return…），按住拖到下方代码的缝隙里 |
| 左下：拼装区 | Routine 源码 + **缝隙投放条**（拖过时高亮：蓝=可放，红=不可）；**黄色行 = 正在执行，灰 = 被优化掉，红 = 卡死**；循环每圈重新高亮 for/while 行 |
| 右上：状态 | 阶段（执行中/等待下一 Tick）、节奏倒计时、CPU 周期余额、行数 x/8、玩家/敌人 HP、击杀数 |
| 右中：变量黑板 | 当前变量值（tick 间持久可见，如 `a = 3`、`x = 4`） |
| 右下：战斗日志 | 每条世界调用（attack/heal/shield）、优化掉警告、Hung 终止、tick 结算 |
| 底部：控制条 | 预设切换、▶运行/⏸暂停、⏭单步一条、⏩快进本 Tick、↺重置运行、语句间隔(默认0.2s)、Tick间隔(默认3s) |

### 拼装编辑操作

| 操作 | 方式 |
|---|---|
| 插入新语句 | 从上面板拖块到缝隙（缝隙变蓝 = 可放） |
| 移动语句 | 按住已有行拖到别的缝隙（含拖进/拖出 if、for 的体） |
| 删除语句 | 右键行 → 删除；或点击选中后按 Delete 键（连同子语句） |
| 改参数 | 双击有数字参数的行（heal(n)、a = 值、循环上限、条件阈值） |
| 撤销 | 暂无（用 ↺ 重置运行 回到预设初始状态） |

行数上限 8（嵌套语句计入），超放会被拒绝（缝隙变红）；把语句拖进它自己的子树也会被拒绝。

## 3. 五个预设

1. **基础输出**：attack(); heal(5); —— 最简观感
2. **连击循环 for(i<x)**：上限 x 是变量（变量面板可见），attack(i*5) 演示表达式参数
3. **保命反击 if(hp<0.5)**：Demo 里玩家持续掉血（假压力），血线跌破 50% 时可以看到分支翻转
4. **变量叠层 a=a+1**：每 tick 计数，a>=3 时重置并放大招——跨 tick 状态机的直观展示
5. **死循环警告 while(true)**：跑到迭代上限被 kill，红色高亮卡在 while 行

## 4. 调度规则（和将来 Unity 版一致）

- 下一 Tick = **max(本 Tick 开始 + TickInterval, 程序跑完时刻)**——程序没跑完绝不开始下一个 tick
- 慢代码 = 错过节奏，是有意的压力设计（Overclock 词缀的两种改法：缩短 TickInterval 或语句间隔）
- 最坏情况被 CPU 预算封顶：约 32 次语句执行 × 0.2s

## 5. 与 Unity 表现层的关系

DemoUI 就是未来 `TickDriver`（Unity 侧 MonoBehaviour）的蓝本：

- 调度逻辑照抄（max 规则、StatementInterval、暂停/单步/快进）
- WinForms 计时器 → Unity 协程（`foreach step in Execute(...) { ...; yield return new WaitForSeconds(interval); }`）
- Label 高亮 → uGUI 文本行
- DemoCombatWorld → 真正的怪/特效/音效

## 6. Demo 里的假东西（别当成正式设计）

- 玩家持续掉血是**演示 hp 分支的假压力**，不是正式的怪物伤害模型
- 敌人是不会动的木桩（120 HP，打空重生计击杀）
- 演出粒度 = 语句步；正式版可能再加"语句内多段演出"
